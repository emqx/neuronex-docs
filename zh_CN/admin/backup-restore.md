# 备份与恢复

EMQX Neuron 提供三种粒度的备份方式，覆盖范围与适用场景不同。

| 方式 | 覆盖范围 | 适用场景 |
| --- | --- | --- |
| [系统备份与恢复](#系统备份与恢复) | 全部配置：南向驱动与北向应用配置、点表、规则、文件与证书 | 升级前留底、整机迁移、故障恢复 |
| [南向设备导入导出](#南向设备导入导出) | 仅南向驱动配置与点位 | 只迁移数采部分、测试环境向现场推配置 |
| [备份数据目录](#备份数据目录) | `/opt/neuronex/data` 下的全部内容 | 停机维护窗口内的冷备份 |

## 系统备份与恢复

在 **管理 → 系统配置** 页面执行。备份将全部配置导出为一个文件；恢复将该文件重新导入，**覆盖**现有配置。

::: warning
恢复过程中 EMQX Neuron 会自动重启，期间采集与转发中断。请在维护窗口内操作。
:::

## 南向设备导入导出

在 **数据采集 → 南向设备** 页面右上角执行，导出为 JSON 文件。范围仅限南向驱动的连接配置与点位，不含北向应用、规则和证书。详见[批量配置与迁移](../configuration/bulk-config.md#南向设备导入导出)。

## 备份数据目录

停止服务后直接复制 `/opt/neuronex/data` 目录。这是与运行状态无关的冷备份，恢复时把目录复制回同一路径即可。目录结构见[数据目录与持久化](./data-persistence.md)。

容器部署时该目录通过 `-v` 挂载在宿主机上，备份宿主机目录即可，见[通过 Docker 部署](../installation/docker.md#启动)。

## 建议执行备份的时机

- **升级前**——升级不会覆盖 `/opt/neuronex/data`，但留一份备份可在需要回滚时直接恢复，见[使用安装包安装 · 升级](../installation/package.md#升级)。
- **批量调整点表前**——[Excel 批量导入](../configuration/import-export/import-export.md)会覆盖同名点位，导入前先导出一份现有配置。
- **主备部署时**——主备两台实例的数采配置需要保持一致，用南向设备导入导出同步，见[主备模式](../best-practise/master-backup.md)。
- **现场交付后**——把最终配置导出留存，便于设备更换时快速恢复。

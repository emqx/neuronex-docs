# 接入大数据与边缘计算

数据要进数据湖做长期分析，或者上报量太大、需要先在边缘过滤和聚合时，用这一类北向应用。

## 两条路径

EMQX Neuron 把数据送进大数据平台有两种走法，可以并存：

| 路径 | 怎么走 | 适合 |
| --- | --- | --- |
| **北向 Kafka 应用** | 南向订阅的数据由北向 Kafka 节点作为生产者直接发送到 Broker/Topic | 采集层已经和订阅模型对齐，希望独立控制发送节奏和 Topic 路由 |
| **数据处理 → Sink** | 南向数据先进[数据处理](../../streaming-processing/overview.md)引擎，SQL 过滤、映射、聚合后再写出 | 需要在边缘删减字段、降采样或按条件上报 |

## 什么时候该在边缘先算一遍

高频采集的原始数据全量上云，成本主要在三处：**上行带宽**、**云端存储**、**云端计算**。以下情况值得先在边缘处理：

- **采集频率远高于业务需要**——100 ms 采一次是为了不漏掉瞬变，但报表只需要分钟级均值。用时间窗口聚合后上报，数据量降两个数量级。
- **大部分时间数值不变**——设备稳态运行时点位值几乎不动。用条件过滤，只在变化超过阈值时上报。
- **需要秒级响应的告警**——判断逻辑放在边缘，不必等云端往返，断网时也能继续工作。
- **上报前要做单位换算或字段重命名**——与其让每个下游系统各自处理，不如在边缘统一好。

规则引擎支持 160+ SQL 函数，覆盖过滤、类型转换、聚合和时间窗口计算，SQL 表达不了的可以用 Python 或 C/C++ 扩展。

## 能写到哪里

除 Kafka 外，数据处理的[动作 (Sink)](../../streaming-processing/sink/sink.md) 还能直接写入：

- **数据库**：MySQL、PostgreSQL、SQL Server、Oracle 等（SQL Sink）
- **时序库**：InfluxDB V1 / V2
- **缓存与消息**：Redis、MQTT、Kafka
- **对象存储与文件**：AWS S3、本地文件、图片
- **接口**：REST 调用

## 用哪个应用

| 应用 | 什么时候用 |
| --- | --- |
| [Kafka](./kafka/overview.md) | 作为 Kafka 生产者把数据写入 Topic，进入大数据平台。支持 SASL 认证和 SSL/TLS 加密，也可对接 Microsoft Fabric Eventstream |
| [规则引擎应用](./ekuiper/overview.md) | EMQX Neuron 内部节点，把南向数据送进数据处理引擎的 `neuronStream` 流。默认已存在，只需添加订阅 |

::: tip
规则引擎处理后的结果也可以通过 Neuron Sink 反写回设备，形成「采集 → 判断 → 控制」的边缘闭环，见 [Neuron Sink](../../streaming-processing/sink/neuron.md)。
:::

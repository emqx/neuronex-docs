# 创建北向应用

南向点位采到之后，用北向应用把数据送到 MQTT、云或处理引擎。协议清单和参数见 [北向应用协议](./catalog.md)。

阅读顺序：

1. 本页：创建北向节点
2. [订阅南向数据](../subscription.md)：把南向组挂到该应用
3. [北向应用协议](./catalog.md)：MQTT、Sparkplug B、Kafka 等

本节以 MQTT 为例。

## 添加北向应用

在 **数据采集** -> **北向应用**，点击 **添加应用**：

* **名称**：应用节点名称，例如 `mqtt`。
* **应用**：选择 **MQTT**。

点击 **创建** 后进入应用配置页。也可以稍后在卡片上点 **应用配置**。

## 设置北向应用参数

在应用配置里填写连接参数。MQTT 各项说明见 [MQTT 应用](./mqtt/overview.md)。

点击 **提交** 后，卡片进入 **运行中**。

## 应用卡片

北向应用页右上角可在列表和卡片之间切换。卡片上的项：

* **名称**：北向应用的唯一名称。
* **应用配置**：填写连接参数。
* **编辑**：修改节点名称。
* **复制**：按原配置生成一个新应用，见[复制北向应用](#复制北向应用)。
* **数据统计**：查看运行统计。
* **DEBUG 日志**：打印当前节点 DEBUG 日志，约十分钟后恢复默认级别。
* **删除**：从列表中删除该节点。
* **工作状态**：
  * **初始化**：刚添加。
  * **配置中**：正在填写配置。
  * **就绪**：配置成功。
  * **运行中**：正在运行。
  * **停止**：已停止。
* **工作状态切换**：打开后与对端建立连接并上报；关闭则断开。
* **连接状态**：与对端是否已连接。
* **应用**：该应用使用的应用名。

## 复制北向应用

在应用卡片上点击 **复制**，填写新名称。新应用带上原节点的应用、连接参数、标签、自定义属性和订阅。client-id、device-id、主题和证书原样复制，不会自动改写。新应用保持停止，需要打开工作状态后才会连接上游。

连接上游前，把必须唯一的标识改成新值，例如 MQTT 的 client-id。两个应用用同一个 client-id 时，后连接的一方会把先连接的一方挤下线。

`monitor`、`DataProcessing`，以及只允许一个实例的应用不能复制。某条订阅对应的南向设备或组已经不存在时，复制失败，不会留下新应用。

## 导出指定应用

在 **数据采集 → 北向应用** 页面右上角点击 **导出**。在列表中选中一个或多个应用时，只导出这些应用；未选中时导出全部北向应用，包括 `monitor` 和 `DataProcessing`。文件为 JSON。

每个应用包含名称、应用、标签、连接参数和订阅。有自定义属性时一并写出。要导出的名称里如果有不存在的应用，其余应用仍会导出。一个都不存在时导出失败。

**导入** 使用导出的文件。同名的普通应用按文件删除后重建，文件中的自定义属性会重新写入。`monitor` 和 `DataProcessing` 不会被删除，只更新连接参数、标签和订阅，文件中的属性不覆盖这两个应用上已有的属性。订阅的南向设备或组不存在时，导入停在这一条。同一实例上再做一个应用，用复制，不用导入。

## 订阅南向数据

点位按组上报。创建北向应用后，需要订阅南向组，步骤见 [订阅南向数据](../subscription.md)。

## 运行与维护

### 数据统计

在卡片或列表中点击 **数据统计**。

![north_statistics](./assets/north_statistics.png)

| 参数 | 说明 |
| --- | --- |
| send_msgs_total | 发送消息总条数 |
| send_msg_errors_total | 发送失败总条数 |
| recv_msgs_total | 接收消息总条数 |
| link_state | 连接状态：DISCONNECTED = 0，CONNECTED = 1 |
| running_state | 节点状态：INIT = 1，READY = 2，RUNNING = 3，STOPPED = 4 |

### 故障诊断

若运行异常，点击 **DEBUG 日志**。系统会打印该节点 DEBUG 日志，约十分钟后切回默认级别。然后在**管理** -> **日志** 页面查看。详见 [管理日志](../../admin/log-management.md)。

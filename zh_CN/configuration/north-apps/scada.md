# 对接上位系统

产线已经建成，SCADA、HMI、MES、历史库和组态软件都在跑，现在要让它们拿到网关采集的数据——但不想改造这些系统。

这一类和其他北向应用方向相反：EMQX Neuron 不主动往外推数据，而是**以 OPC UA 标准对外提供服务**，上位系统作为客户端主动连进来，浏览地址空间、订阅点位变化、读取实时值，也可以反向下发控制指令。

## 价值在于上位机侧零改造

SCADA、HMI、组态软件本来就会说 OPC UA——这是工业自动化领域事实上的标准接口。接上之后：

- **上百种设备协议统一成一个数据源**。南向接入的 Modbus、西门子 S7、三菱、欧姆龙、CNC、电力 IEC 系列不再需要逐个对接，上位系统只面对一个 OPC UA Server。
- **上位系统不用改代码，也不用买驱动**。以往为每种 PLC 单独采购 OPC 驱动或写通讯程序的成本省掉了。
- **新增设备对上位系统透明**。在 EMQX Neuron 侧加一个南向驱动并订阅，点位自动出现在地址空间里。

## 地址空间怎么组织

EMQX Neuron 把**已订阅**的点位映射为 OPC UA 节点，层级和现场结构一致：

```
EMQX Neuron
└── modbus-tcp-1          南向驱动 → 对象节点（Object）
    └── group-1           采集组   → 子对象
        └── temperature   点位     → 变量节点（Variable）
```

NodeId 规范为 `ns=1;s=[南向设备名].[组名].[点位名]`，例如 `ns=1;s=modbus-tcp-1.group-1.temperature`。上位系统按这个规则批量配置标签即可，不需要手工浏览。

::: warning
只有被订阅的组，其点位才会出现在地址空间中。创建应用后必须[添加订阅](../subscription.md)，否则客户端连上来看不到任何变量节点。
:::

## 安全

OPC UA 在工厂网络里通常承载控制指令，安全配置不是可选项：

- **安全策略**：支持 None、Basic256Sha256、Basic256、Basic256Rsa15、Aes128_Sha256_RsaOaep。生产环境建议用 Basic256Sha256，客户端启用 SignAndEncrypt 模式。
- **证书双向校验**：首次启动生成服务端自签名证书，客户端需要手动信任；陌生客户端的证书进入非信任列表，需在界面手动放行后才能连接。
- **用户名密码认证**：支持新增用户、更新密码和删除用户。

## 反控

OPC UA 客户端对变量节点执行写操作，值就下发到设备，不需要额外配置主题或通道。点位需要在南向驱动中带 **write** 属性，见[组与点位 · 点位属性](../groups-tags/groups-tags.md#点位属性)。

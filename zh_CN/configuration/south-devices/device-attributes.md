# 设备属性

设备属性用于为南向设备补充静态信息，例如设备编号、安装位置、所属产线和设备型号。这些信息不需要从设备寄存器中采集，可以在南向设备上统一维护，再通过 **MQTT V2** 随设备状态或采集数据上报，帮助下游系统识别数据来源。

例如，一台设备的温度、电流作为点位周期采集，设备编号和所属产线作为设备属性配置。下游系统收到消息后，就可以按设备编号关联资产，或按产线归类采集数据。

::: tip
本页的上报配置适用于 **MQTT V2** 应用。设备状态消息自动携带设备属性；采集数据消息默认不携带，需要在模板中显式引用。
:::

## 设备属性与点位的区别

| 配置项 | 配置位置 | 用途 |
| --- | --- | --- |
| **设备属性** | 南向设备的 **属性** 标签页 | 维护设备级静态信息。订阅该设备的所有 MQTT V2 应用都可以使用，不需要在每个应用中重复配置 |
| **采集点位** | 南向设备的采集组内 | 通过协议读取或写入设备数据，例如温度、电流和开关状态，见[组与点位](../groups-tags/groups-tags.md) |

设备属性属于设备，不属于某个采集组。同一设备的多个组上报时，可以引用同一组设备属性。

## 配置设备属性

### 前提条件

- 已[创建南向设备](./south-devices.md)，并配置至少一个[采集组和点位](../groups-tags/groups-tags.md)。
- 如需验证 MQTT 上报，已准备一个可从 EMQX Neuron 运行环境访问的 MQTT Broker，以及 MQTTX 等 MQTT 客户端。
- 当前版本的北向应用列表中提供 **MQTT V2**。

### 添加属性

1. 在 **数据采集 → 南向设备** 页面进入目标设备，打开 **属性** 标签页。
2. 添加属性，填写属性名和对应的属性值，并保存。
3. 确认属性列表中的名称、值和数据类型符合预期。

以下以南向设备 `modbus-1` 为例，配置三项属性：

| 属性名 | 属性值 | 数据类型 | 用途 |
| --- | --- | --- | --- |
| `asset_id` | `M-001` | 字符串 | 设备的资产编号 |
| `location` | `Building A` | 字符串 | 设备的安装位置 |
| `line` | `3` | 整数 | 设备所属产线 |

其对应的数据为：

```json
{
  "asset_id": "M-001",
  "location": "Building A",
  "line": 3
}
```

以上是属性数据的 JSON 表示，用于说明名称、值和类型之间的对应关系。

### 支持的数据类型

属性值支持字符串、布尔、整数、浮点数，以及**元素类型相同的一维数组**。

| 数据类型 | 示例 |
| --- | --- |
| 字符串 | `"M-001"` |
| 布尔 | `true` |
| 整数 | `3` |
| 浮点数 | `1.5` |
| 一维数组 | `["zone-a", "zone-b"]`、`[1, 2, 3]` |

不要使用对象、嵌套数组或元素类型混合的数组。例如 `{"floor": 1}`、`[[1, 2], [3, 4]]` 和 `[1, "zone-a"]` 不属于支持的属性值类型。

数值 `3` 与字符串 `"3"` 的含义不同。配置时应按下游系统要求选择类型，避免后续筛选、计算时出现类型不匹配。

## 通过 MQTT V2 上报属性

### 配置应用和订阅

1. 在 **数据采集 → 北向应用** 页面添加应用，选择 **MQTT V2**，本例将应用命名为 `mqtt-properties`。
2. 配置 MQTT Broker 的地址、端口及所需的认证信息，并为应用设置不与其他连接重复的客户端 ID。
3. 保留默认的 **Topic 前缀** `neuron/${app}`。本例中实际前缀为 `neuron/mqtt-properties`。
4. 进入该应用的 **组列表**，添加对南向设备 `modbus-1`、采集组 `group-1` 的订阅。保留默认数据主题 `${prefix}/${device}/data`。
5. 确认 MQTT V2 应用正在运行，并已连接 Broker。

本例使用以下两个主题：

| 消息 | Topic | 是否自动携带设备属性 |
| --- | --- | --- |
| 设备状态 | `neuron/mqtt-properties/modbus-1/state` | 是，属性平铺在消息顶层 |
| 采集数据 | `neuron/mqtt-properties/modbus-1/data` | 否，需要配置模板 |

设备至少有一个组被该应用订阅后，应用才会为其发布设备状态。设备状态消息的结构固定，不受数据模板或点位模板影响。

### 在设备状态消息中查看属性

使用 MQTTX 连接同一个 Broker，并订阅：

```text
neuron/mqtt-properties/modbus-1/state
```

设备状态消息会自动带上已配置的属性，格式示例如下：

```json
{
  "timestamp": 1731744000123,
  "name": "modbus-1",
  "state": 1,
  "running": 3,
  "asset_id": "M-001",
  "location": "Building A",
  "line": 3
}
```

- `timestamp`、`name`、`state`、`running` 是固定字段。其中 `state: 1` 表示已连接，`running: 3` 表示运行中。
- `asset_id`、`location` 和 `line` 是设备属性，直接平铺到消息顶层，不包在 `properties` 对象中。
- 设备状态使用 **QoS 1**，并设置 **Retain**。新订阅者可以收到 Broker 保留的最近一条状态；这不代表设备在订阅时刚发生了状态变化。
- 属性新增、修改或删除后，应用会立即重新发布设备状态；与 Broker 断开连接期间不发布，重连后重新发布最新状态。

::: warning 属性命名
`timestamp`、`name`、`state`、`running` 是设备状态消息的固定字段。与它们同名的设备属性不会出现在状态消息中。建议使用 `asset_id`、`location` 等业务名称，避免冲突。
:::

### 在采集数据消息中携带全部属性

MQTT V2 的默认数据模板不包含设备属性。若需要随采集数据一起发送，在应用的 **数据模板** 中加入 `${properties}`：

```json
{
  "timestamp": "${timestamp}",
  "device": "${device}",
  "group": "${group}",
  "properties": "${properties}",
  "tags": "${tags}"
}
```

**点位模板** 保持默认即可。保存配置后，在 MQTTX 中订阅：

```text
neuron/mqtt-properties/modbus-1/data
```

假设 `group-1` 中的 `tag0` 采集值为 `123`，上报格式示例如下：

```json
{
  "timestamp": 1731744000123,
  "device": "modbus-1",
  "group": "group-1",
  "properties": {
    "asset_id": "M-001",
    "location": "Building A",
    "line": 3
  },
  "tags": [
    {
      "name": "tag0",
      "value": 123
    }
  ]
}
```

这里的 `properties` 是数据模板中指定的字段名，可以按下游系统要求改为其他名称；`${properties}` 才是引用设备属性的模板变量。

### 只上报指定属性

如果下游系统只需要部分属性，或者要求属性位于消息顶层，可使用 `${properties[属性名]}`。例如：

```json
{
  "timestamp": "${timestamp}",
  "device": "${device}",
  "asset_id": "${properties[asset_id]}",
  "site": "${properties[location]}",
  "line": "${properties[line]}",
  "tags": "${tags}"
}
```

上报格式示例如下：

```json
{
  "timestamp": 1731744000123,
  "device": "modbus-1",
  "asset_id": "M-001",
  "site": "Building A",
  "line": 3,
  "tags": [
    {
      "name": "tag0",
      "value": 123
    }
  ]
}
```

模板中的变量需要写在 JSON 字符串中。字符串中只有一个变量时，替换结果会保留原本的 JSON 类型，所以 `"${properties[line]}"` 输出的是整数 `3`，不是字符串 `"3"`。变量与文字混写时才会拼接成字符串。

`${properties}` 和 `${properties[属性名]}` 也可以用于点位模板，例如在每个点位对象中加入设备编号。

## 验证配置

完成配置后，按以下顺序检查：

1. **检查状态消息**：订阅设备的 `/state` 主题，确认三项属性均出现，且 `line` 为数值类型。
2. **检查数据消息**：订阅设备的 `/data` 主题，确认配置模板后，属性与采集点位出现在同一条消息中。
3. **检查属性更新**：将设备属性 `location` 从 `Building A` 修改为 `Building B` 并保存，确认收到重新发布的状态消息，以及后续数据消息中的新属性值。
4. **检查共享范围**：如果同一设备有多个采集组或被多个 MQTT V2 应用订阅，检查各应用的状态消息；需要携带属性的数据消息，应分别在对应应用模板中配置引用。

本文中的 JSON 均为格式示例，实际时间戳、设备状态和点位值以运行环境为准。
